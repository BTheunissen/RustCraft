## Items, inventory, and persistence

- `game/item` distinguishes `Item::Block(Block)` from `Item::Tool(Tool)`;
  `Tool::StonePickaxe/StoneAxe` IDs 0/1 are independent of voxel/atlas IDs.
  `ItemStack { item, count }` validates collectible solids (not bedrock) with
  count 1..64, tools with count exactly one. Selection in the existing nine-slot
  hotbar equips a tool; only block items can place or be consumed by placement.
- Item insertion returns all leftover quantities. Keep a small block-insertion
  convenience so existing gameplay/diagnostics do not need an artificial item API.
  Pickups contain items, not pretend tool blocks; merge respects each item's cap.
- Left-click lifts/moves/merges/swaps stacks. Right-click lifts half (rounded up)
  or transfers one held item. A split keeps its original slot reserved; a swap
  is allowed only when its newly held result can be restored into that reservation.
  No operation may lose cursor items. Automatic insertion/crafting excludes the
  reserved source and held stack. Close/pause/focus/save restores reservations.
- Cross-inventory crate cursor ownership stays with `game`, not GPU/UI. One
  explicit reserved source (player or crate slot) must cover the held stack after
  any accepted transaction. Invalid/full transfer is a no-op; opening/closing/
  saving normalizes transient cursor state without changing item totals.
- Save format deliberately **1 → 2** for tagged item records; generation stays
  **2**, existing voxel IDs unchanged. Encode item tag and u8 ID plus u16 count;
  only an explicit empty tag/zero ID/zero count represents an empty slot. Tools
  are never interpreted as old block IDs. Add format **3** when sparse crate
  records land; no migration, automatic replacement, or real-save test access.
  Incompatible slots stay occupied with backup/confirmed-fresh-world errors.

## Materials and recipes

Append only Planks=23, DressedLimestone=24, StorageCrate=25, Lantern=26 as their
working slices land. All are ordinary solid full cubes with original textures,
names, icons, held/drop presentation, phasing mapping, collision, and saves.
None is generated by terrain; default/42 goldens remain unchanged.

| Inputs | Output |
| --- | --- |
| 1 Wood | 4 Planks |
| 1 Limestone | 1 Dressed Limestone |
| 4 Planks + 3 Stone | 1 Stone Pickaxe |
| 4 Planks + 2 Stone | 1 Stone Axe |
| 8 Planks | 1 Storage Crate |
| 2 Planks + 1 Crystal | 1 Lantern |

Recipes consume available slots only (not held/reserved source), calculate
capacity **after** consuming, and commit one complete copied transaction.
Missing inputs/full output/invalid recipe leave the original inventory exactly
unchanged. Expose only delivered recipes; inventory remains paused. No grid,
workbench, unlocks, furnace, metals tree, durability, fuel, or access gates.

Pickaxe is **3×** faster for stone/deep stone/limestone/slate/basalt/calcite,
ores/crystal, and dressed limestone; axe is **3×** faster for wood/planks/crate.
Other materials keep hand duration. Bedrock/liquids/air remain unmineable.
Switching selected tools/targets or releasing/pausing resets mining; progress
uses the actual active duration. One ordinary block drop, no tool consumption.
Tools have distinct original HUD icons and held cuboid silhouettes; no fake cube
or voxel/atlas renumbering. Reuse restrained M2 feedback without duplicate break.

## Storage

- Sparse `game` crate map keyed by `[i32;3]`, at most **4096 crates**, exactly
  **18 slots** each. Snapshot validates unique coordinates, item caps, and each
  record's corresponding placed `StorageCrate` override. Generated chunks are
  not saved; contents outlive eviction.
- Right-click a reachable resident crate opens it; **Shift+right-click** requests
  ordinary placement against it. This explicit modifier is independent of swim
  descent. Opening suspends movement/mining, releases capture, and clears input.
- A crate must be empty and have no held reserved items before mining. Reject
  nonempty removal with a clear HUD notice; do not scatter/delete contents.
  Removing an empty crate drops exactly one crate block and deletes its record.
- Transfer/split/merge/swap tests conserve every item across both inventories,
  full destinations, cursor close, focus loss, save snapshots, eviction, and
  Continue. A stale/out-of-reach/unloaded target cannot open or mutate storage.

## Lantern illumination

Use a bounded CPU warm-light flood through actual edited voxels, generated on
the existing meshing worker from the same immutable edit snapshot. Source reach
**8 voxel steps**, six-neighbor attenuation; solids block transport, water can
carry attenuated light. A surface samples adjacent air light, not a glowing
texture or an unbounded shader emitter loop.

A chunk's fixed eight-block halo fits the existing 3×3 edit dependency/revision
policy. Bound source discovery to those sparse chunk maps; when no lantern is
present, skip the flood/extra terrain work. Build at most a 32×32×world-depth
field for an affected mesh, with fixed-capacity grids/descending integer levels and no global source
scan. RGB vertex payload carries local warm illumination separately from sky,
water metadata, global irradiance, and headlamp; do not accidentally feed it into
the sky/air/fog enclosure test. Lanterns are excluded from long-range global
probe emission so the strict local-radius contract remains meaningful.

Placing/removing sources/walls invalidates dependent neighbor meshes; stale
worker responses remain rejected. Rebuild/reload must produce identical field
and payload. CPU tests cover falloff, source overlap, sealed walls, openings,
negative seams/Y, edits/revisions/removal. Native same-pose headlamp-off dark
room checks exclude HUD/source pixels and verify receiver surfaces, far-side
occlusion, and distant cave darkness. Preserve ordinary sunlight/headlamp/water/
cutaways; if illumination needs broader engine changes, stop rather than pretend
an emissive cube meets the requirement.
