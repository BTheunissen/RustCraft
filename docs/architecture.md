# Architecture

One Cargo package, one library, one thin executable. Modules provide useful boundaries without a framework, plugin registry, or a premature multi-crate workspace.

## Ownership and dependency direction

```text
main → app (composition/native events)
         ├─ game → player, lighting, world
         ├─ streaming → mesh → world, lighting, water
         ├─ save → game (progress snapshots), player, world
         └─ renderer → camera, mesh, hud, phase, game, world
```

- `world/` owns stable materials, coordinates, biomes, fluid contracts, chunk storage, and CPU residency. Its private `generation/` pipeline composes surface relief, hydrology, bounded coastal occupancy, underground geology, and rooted decorations. Coastal projection follows the original hydrology filter; bedrock remains first, seals protect designed rock, trees stay outside coastal occupancy, and sparse player edits apply last. Arch roofs are explicit solid intervals distinct from ground/water; chunk roof metadata is a bounded hint, never voxel authority.
- `player/` handles logical movement, swept collision, and swimming through read-only world callbacks. `game/` owns mode rules, terrain, resident chunks, player state, inventory, mining, pickups, environment sampling, headlamp, persistent creative speed, and an independent bounded solar clock. Solar speed never scales physics or animation; all application overlays/focus loss suspend clock updates.
- `streaming` prepares CPU chunks/meshes. The application inserts/evicts CPU residency and GPU geometry together; **rendering does not own the world**. A `WorldView` makes resident-only reads and explicit procedural fallback separate choices.
- `renderer/` owns GPU/surface resources, passes, uniforms, and readback. Cutaway and lighting caches borrow resident voxels and invalidate only overlapping chunk revisions. HUD geometry and camera/lighting math remain CPU-only. `lighting/` owns voxel-ID reflectance/emission, stable cascade math, full-height resident sky transmission, fixed probe scheduling, and bounded exposure; it does not own a GPU, terrain generation, or gameplay.
- `app/` translates native events and manages presentation pacing. Bounded diagnostic scenes live in private `playtest/`, not in interactive gameplay or world shortcuts.
- `game/feedback` supplies bounded transient CPU results, never saved or dependent on playback. An internal 30-step `player` report measures actual supported displacement/wet transitions; material reads only occur when a step is due. Ambience performs at most 289 resident surface-water reads at 4 Hz, never generating terrain or retaining chunk caches. Private `app/audio` preloads original samples and owns a device-free bounded mixer plus CPAL/native worker. Atomic lifecycle epochs and a nonblocking bounded mailbox separate the callback from gameplay, disk, generation, and rendering; ordinary tests/graphics smoke never open audio hardware.
- `game/coastal_route` is an explicit CPU diagnostic, not a per-frame system: bounded resident sampling and A* test real support/full-body/headroom, then replay routes forward/reverse with `player/`. `lighting/exposure` distinguishes short exposed coastal roofs from cave enclosure. Mesh sky-spill halos are generated/cached on the worker from the same edit snapshot; renderer cavity reads are resident-only. Existing 3×3 dirty/revision halos include the eight-block lateral reach.
- `game/snapshot` captures and restores renderer-independent progress without dense residency or physical input. `save/` owns the bounded versioned file format, per-user local path, validation, and same-directory atomic replacement. `app/persistence` schedules wall-clock autosaves; `app/session` saves before replacing/leaving scenes. CPU gameplay never depends on disk storage.
- `game/item` distinguishes collectible blocks from nonstackable permanent tools; recipe/transfer transactions own counts, not UI geometry. `game/storage` owns at most 4096 sparse 18-slot crates and one explicit player/crate reserved cursor. Snapshot normalization returns held items without mutating the live UI; format 3 validates tagged items and every unique crate association with a placed override. Generation remains 2.
- `lighting/lantern` computes at most 32×32×world-depth cells through eight descending integer levels, no unbounded emitter/queue scan. `mesh/lanterns` discovers sources in fixed sparse 3×3 chunk maps and generates the edited halo only on the worker when needed. `Vertex::local_light` adds separate warm RGB; it never modifies skylight/camera exposure/water occupancy. Existing halo revisions reject stale fields; native/GPU resources stay in the renderer, lanterns do not emit into long-range probes.
- Probe slots are world-grid toroidal addresses, not camera-local indices. Camera scrolls retain overlap and fill entering probes before shading; scene/occupancy invalidation recomputes the bounded grid before drawing. Ordinary 512-probe batches are spatially interleaved. CPU atlas mip generation remains in `atlas/`, while texture arrays, sampling, and independent motion/reference readback belong to `renderer/`.
- `lighting/celestial` maps one solar hour to shared direction/radiance/sky/cloud colors. Camera enclosure and mesh skylight remain time-independent. Direct surfaces, cascades, probe bounce, water, and shadowed air consume the same sample; local emitters and headlamp remain independent. Explicit phase jumps/horizon crossings refresh the bounded probe grid once; normal ticks retain 512 probes, accelerated ticks raise complete-batch budgets up to 4,096 to bound stale solar angle. `app/time_console` owns bounded keyboard-only debug input and capture authorization; `hud/time_console` only paints. Format 4 appends an exact solar hour; format 3 loads unchanged at 10:00, while debug speed remains session-only.

## Survival and presentation contracts

- Sparse block edits belong to `world/`, not the terrain generator or renderer. Resident edits mutate CPU voxels immediately and survive eviction; regeneration and procedural fallback apply the same overlay. Save snapshots include unloaded edits and dormant pickups. Continue restores overlays before the first streaming request; returning to the menu clears live residency only after a successful save.
- `streaming/` snapshots edits for bounded worker generation/remeshing, coalesces dirty chunks, and rejects outdated revisions. Edited boundary columns affect neighboring meshes and daylight; generated material IDs and terrain fingerprints remain stable.
- `game/` performs resident-only interaction targeting, timed hand mining, conservative inventory transfers, pickup physics, and validated placement. Targeting skips zero-length edge/corner touches; pickup visibility checks those side cells conservatively so items cannot be collected through diagonal walls. Creative mode rejects survival interactions; survival rejects creative flight/speed actions at the gameplay boundary.
- `app/` owns menu/loading/playing/inventory/crafting/storage/pause/audio-controls/replacement-confirmation transitions and capture. All overlays suspend simulation, not autosaves; screen/focus changes clear held buttons/jump/mining and restore cursor reservations. UI clicks cannot fall through into world interactions. Right-click opens a resident reachable crate, Shift requests placement against it; nonempty mining rejects visibly. Audio preferences are independently bounded/atomic and cannot block progress saves. Smoke never autosaves player files. Save failures keep the scene and show the paused notice; replacement requires confirmation even for corrupt/incompatible files.
- `hud/` borrows CPU gameplay readouts for menu/hotbar/inventory geometry and shared hit-test layout, plus original atlas/material mappings for icons. It does not mutate gameplay or access native/GPU resources. `renderer/` draws pickups, target feedback, and the first-person hand separately from chunk geometry; temporary mining cracks never trigger a chunk rebuild.
- Presentation order is sunlight depth cascades → fixed-budget voxel probe compute → HDR sky/opaque/pickups/water/cutaway with a ray-depth/fog guide → half-resolution shadowed air → depth-aware HDR air composite → first-person hand → highlight bloom and tone mapping → display-space HUD. Air replaces the sun share of the same fog transmittance, not a second fog layer; water/lava/cutaway media remain separate. Off-camera casters use light-frustum visibility, not the camera's visible-chunk list. Original vertex skylight remains atmosphere/water metadata; shadows and colored irradiance use separate GPU bindings. Diagnostic full updates produce deterministic comparisons, and separate GPU acceptance checks exercise the actual eight-frame interactive schedule and compare upscaled air against full-resolution rays.

Public entry points are `run`, launch options, and the CPU-facing modules. Generator/native implementation modules stay private; use `pub(super)` or subsystem-scoped visibility when internals must collaborate.

## Keep it maintainable

`cargo test --locked` includes `tests/architecture.rs`: CPU dependency direction, native/GPU isolation, a **650-line ceiling per Rust file** (including tests/examples), and a thin `main`. These are backstops, not a reason to split a cohesive function arbitrarily. Unit tests stay beside their subsystem in dedicated files; integration suites exercise public contracts. Extend responsibilities through the owning module instead of adding a generic service layer.

Formatting, strict all-target Clippy, regression tests, and native smoke checks remain the normal workflow. Unsafe code is forbidden. Audio uses the owner-approved exact CPAL 0.18.2 dependency; no framework, codec, CI, hooks, task runner, or corporate tooling is required. Golden fingerprints protect existing default/seed-42 terrain and fluid metadata during structural changes; update them only for an intentional generation change.
